# OrbitGuard Backend

FastAPI service implementing threat detection, maneuver planning, counterfactual
simulation, and final decision-making for the OrbitGuard conjunction response
pipeline. Owned by Member 2 per the Project Bible, Section 5.

## Setup

```bash
cd backend
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Running

```bash
uvicorn main:app --reload --port 8000
```

Server runs at `http://localhost:8000`. Interactive API docs (auto-generated by
FastAPI) are available at `http://localhost:8000/docs`.

## Endpoints

| Method | Path                  | Purpose                                        |
|--------|-----------------------|-------------------------------------------------|
| GET    | `/api/scenario`       | Current object set (satellites + debris)        |
| POST   | `/api/scenario/reset` | Reload `data/mock_scenario.json`                |
| GET    | `/api/threats`        | Run detection, return active conjunctions       |
| POST   | `/api/plan`           | Candidate maneuvers for a given threat          |
| POST   | `/api/simulate`       | Counterfactual check for one candidate plan     |
| POST   | `/api/decide`         | Full pipeline: score, verify, final decision    |
| POST   | `/api/approve`        | Human sign-off flag (optional, frontend can also do this purely client-side) |

All request/response shapes match **Section 4 of the Project Bible exactly**
(`models.py`). Field names are frozen — do not rename anything here without
updating `contracts/` and notifying the team.

## Module layout
backend/
main.py FastAPI app, route definitions only
models.py Pydantic models matching Section 4
propagation.py Two-body Keplerian orbit propagation
conjunction.py Pairwise distance search, risk scoring
maneuver.py Candidate maneuver generation (raise/lower/phase/wait)
simulator.py Counterfactual check - also serves as the Verifier (5.6)
commander.py Deterministic scoring (6.4) + replan logic (2.4)
data/
mock_scenario.json Synthetic demo scenario
## Design notes / simplifications (intentional, per Section 9)

- **Propagation**: uses simplified two-body Keplerian propagation instead of
  full SGP4/TLE parsing. This is the sanctioned fallback (Section 9.1) — our
  scenario objects are defined with clean synthetic Keplerian elements, not
  TLE lines, so full SGP4 would add complexity without adding accuracy here.
- **Risk score**: a defensible heuristic (Section 5.3), not a full
  covariance-based probability-of-collision model. Say so plainly if asked by
  judges.
- **Verifier is not a separate module**: it's `simulator.py`'s
  `check_candidate()` function called a second time on the Commander's
  selected plan (Section 5.6). If it fails, the Commander tries the
  next-best feasible candidate exactly once, then stops (Section 2.4).
- **The `justification` field in `/api/decide`'s response is currently a
  placeholder string** written by deterministic Python
  (see the `TODO` comment in `commander.py`). The AI Agent (Member 4) should
  call `/api/decide`, take the full JSON response, and generate the real
  justification text via Gemini using `selected_plan`, `scores`,
  `rejected_plans`, and `verification` — no backend changes needed for them
  to start.

## The finalized demo scenario

Tuned specifically so the counterfactual-rejection story (Section 8.4) plays
out exactly as scripted:

- **Threat**: `SAT-03` (CommSat-Alpha, critical) vs `DEB-17`, miss distance
  0.41 km, relative velocity 14.3 km/s, risk score 0.918, severity **HIGH**.
- **PLAN-1** (raise_orbit): resolves the primary threat but creates a **new**
  conflict with `SAT-05` (0.30 km, risk 0.94) → REJECTED.
- **PLAN-2** (lower_orbit): fully feasible, but loses to PLAN-3 on score
  (higher fuel cost) → REJECTED.
- **PLAN-3** (phase_shift): resolves cleanly, no secondary conflicts →
  **SELECTED**, verified SAFE.
- **PLAN-4** (wait): does not resolve the original threat within the
  propagation window → REJECTED.
